# ระบบตรวจจับ BSF — Desktop App (Python / PySide6)

แอปเดสก์ท็อปที่เขียนด้วย Python ใช้ **PySide6** (Qt) สำหรับ GUI,
**OpenCV** สำหรับเปิดกล้อง/ประมวลผลภาพ และ **Railway MySQL** สำหรับจัดเก็บข้อมูล

## เริ่มใช้งาน

1. ติดตั้งครั้งแรกด้วย `install.bat` (Windows) หรือ `install.sh` (macOS/Linux)
2. เปิดโปรแกรมด้วย `run.bat` (Windows), `run.command` (macOS) หรือ `run.sh` (Linux)

## โครงสร้างไฟล์

ไฟล์ที่ใช้พัฒนาระบบและข้อมูลของโปรแกรมรวมอยู่ในโฟลเดอร์ `pg/`

| ไฟล์/โฟลเดอร์ | หน้าที่ |
|---|---|
| `pg/main.py` | GUI และการทำงานหลักของโปรแกรม |
| `pg/detector.py` | โหลดโมเดลตรวจจับจาก `pg/best_2.pt` |
| `pg/database.py` | สร้างตารางและอ่าน/เขียนประวัติผลตรวจจับใน MySQL |
| `pg/mysql_database.py` | โหลดค่าตั้งค่าและเชื่อมต่อ Railway MySQL |
| `pg/.env.example` | ตัวอย่างค่าตั้งค่าสำหรับ Railway (คัดลอกเป็น `.env`) |
| `pg/requirements.txt` | รายการไลบรารีที่สคริปต์ติดตั้งใช้ |
| `pg/` | ไฟล์ทำงาน โมเดล ฐานข้อมูล และ virtual environment |

## ฐานข้อมูล

แอปใช้ตาราง `detections` (ผลตรวจจับ), `tray` (ถาดของผู้ใช้) และ `users`
ใน MySQL หน้า "ประวัติ" อ่านข้อมูลผ่าน `get_history(user_id)` และแสดงเฉพาะ
รายการตรวจจับของบัญชีที่เข้าสู่ระบบ โดยบันทึกเจ้าของไว้ใน
`detections.user_id` ถาดแต่ละรายการเชื่อมกับเจ้าของผ่าน `tray.user_id`
และชื่อถาดอยู่ใน `tray.tray_name`
คอลัมน์ `detections.full_count` เก็บจำนวนตัวอ่อนทั้งหมด ซึ่งคำนวณจากผลรวม
ของระยะที่ 2, 3 และ 4 และแสดงทั้งหน้าตรวจจับกับหน้าประวัติ

ผู้เยี่ยมชมตรวจจับได้ แต่ไม่เห็นประวัติหรือถาด และบันทึกผลไม่ได้ ต้องเข้าสู่ระบบ
ก่อนจึงจะเห็นประวัติ ใช้ถาดของบัญชีตนเอง และบันทึกผลตรวจจับได้

ผลตรวจจับเดิมที่ไม่มี `detections.user_id` จะไม่แสดงในประวัติของบัญชีใด
เพื่อป้องกันการเปิดเผยข้อมูลข้ามบัญชี

ข้อมูล SQLite เก่าที่ `pg/bsf_data.db` จะไม่ถูกลบ แต่ไม่ได้ย้ายไป MySQL โดยอัตโนมัติ

## เข้าสู่ระบบ

ผู้ใช้สามารถสร้างบัญชีด้วย username, email และ password แล้วเข้าสู่ระบบด้วย
username หรือ email ก็ได้ หรือเลือกใช้แบบผู้เยี่ยมชม บัญชีถูกบันทึกในตาราง
`users` บน Railway MySQL โดย password จะเก็บเป็น salted PBKDF2 hash
ไม่เก็บเป็นข้อความธรรมดา ชื่อผู้ใช้ยาว 3-50 ตัวอักษร (a-z, 0-9 และ `_`)
และ password ต้องยาวอย่างน้อย 8 ตัว ตาราง `users` ใช้คอลัมน์
`user_id`, `username`, `email` และ `password_hash`

## ตั้งค่า Railway MySQL

1. สร้าง MySQL service ใน Railway และเปิด **Settings → Networking → Public
   Networking** เพื่อให้แอปเดสก์ท็อปภายนอก Railway เชื่อมต่อได้
2. คัดลอก `pg/.env.example` เป็น `pg/.env`
3. นำค่า `MYSQL_PUBLIC_URL` จากหน้า Variables ของ Railway มาใส่ใน `pg/.env`
   แทนค่าตัวอย่าง โดยไม่ต้องใส่เครื่องหมาย quote
4. ติดตั้ง dependencies ใหม่ด้วย `install.bat` แล้วเปิดแอปด้วย `run.bat`

เก็บ `pg/.env` เป็นความลับและอย่าส่งไฟล์นี้ขึ้น Git หรือแชร์ต่อ ไฟล์นี้ถูก
ตั้งค่า ignore ไว้แล้ว รองรับตัวแปร Railway `MYSQLHOST`, `MYSQLPORT`,
`MYSQLUSER`, `MYSQLPASSWORD`, `MYSQLDATABASE` เป็นทางเลือกด้วย แต่สำหรับ
แอปที่รันนอก Railway ให้ใช้ `MYSQL_PUBLIC_URL` ซึ่งเข้าถึงผ่าน public TCP proxy

เมื่อเริ่มแอป จะทดสอบการเชื่อมต่อและสร้างตารางที่ยังไม่มี หากเชื่อมต่อไม่ได้
แอปจะแสดงข้อความผิดพลาดพร้อมคำแนะนำในหน้าต่าง การเข้าสู่ระบบทดลองยังไม่เก็บ
บัญชีหรือรหัสผ่านลงฐานข้อมูล

## หมายเหตุเรื่องกล้อง

โหมดวิดีโอและกล้องเรียลไทม์ใช้ ByteTrack ติดตามตัวอ่อนระหว่างเฟรม
พร้อมแสดง Track ID บนกรอบตรวจจับ เมื่อหยุดตรวจ ระบบสรุปจำนวนตัวที่ติดตามได้
แบบไม่ซ้ำ โดยจัดระยะตามคลาสที่ตรวจพบมากที่สุดต่อ Track ID ส่วนโหมดรูปภาพ
ยังนับผลตรวจจับจากภาพเดียวตามปกติ หลังตรวจจับรูปภาพแล้วกด "ขยายรูป"
เพื่อดูภาพผลลัพธ์ขนาดใหญ่ หมุนล้อเมาส์เพื่อซูมและลากเพื่อเลื่อนภาพ

ถ้ามีกล้องหลายตัวและ `cv2.VideoCapture(0)` ไม่ตรงกับกล้องที่ต้องการ
ให้เปลี่ยนเลข index (0, 1, 2, ...) ใน `pg/main.py` ฟังก์ชัน `_start_detection`
